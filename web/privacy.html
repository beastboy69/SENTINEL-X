This page describes the included local prototype. Before public launch, the project owner must verify this text against the deployed service, hosting provider, analytics, contact process, and any future data collection.

1. What this prototype processes

The default build creates synthetic event fixtures and stores event metadata and rule findings in a local SQLite database file named sentinel_x.db. It does not automatically read Windows Event Viewer logs, transmit endpoint logs to a third party, or change endpoint security settings.

2. Network requests and server logs

The local interface sends requests to the local Python API that serves it. The server writes basic request status information to its console. The default server binds to 127.0.0.1. A deployment, reverse proxy, hosting provider, or added feature may process additional technical data; this document must be updated if that happens.

3. Data storage and deletion

Demo records are stored in the local SQLite database until the database is deleted or records are otherwise removed. Keep real security logs, credentials, tokens, personal information, and sensitive scripts out of this demo. Back up or delete the database only according to your own data-handling requirements.

4. Third-party services

The provided local prototype has no analytics or external AI service integration. If hosting, analytics, error monitoring, or external AI services are added, identify those providers and describe their data handling before launch.

5. Security and limitations

This is a hackathon prototype, not a production security product. Do not expose the development server publicly. Public deployment requires a security review, access controls, HTTPS, data-retention decisions, and an updated privacy assessment.

6. Contact and policy updates

Before public launch, publish a monitored project contact address and identify the responsible operator. Do not launch with placeholder or invented contact information. Update this policy whenever actual processing changes.
